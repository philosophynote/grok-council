# Grok Council

Grok (xAI) API を使って著名人に相談し、著名人同士が討論し、司会が総括する Web アプリです。
すべての発言はストリーミングで表示され、総括のあとは、同じ参加者に追加質問して討論を続けられます。

- 技術: Next.js 16 (App Router) / React 19 / AI SDK 7 (`ai`, `@ai-sdk/react`, `@ai-sdk/xai`) / Chakra UI v3 / zod 4
- 対象: ローカルで自分用に動かす前提です。認証・レート制限・同時実行制限は実装していません

## 免責事項

- 登場する人物は、実在・歴史上の人物をモチーフに AI が演じる架空のキャラクターです。本人および関係する団体・企業とは一切関係がなく、承認や監修も受けていません
- 画面に表示される発言は AI が生成したものであり、本人の発言・見解ではありません。人物像や思想は意図的に誇張・単純化しており、事実と異なる内容を含むことがあります
- 一部の人物は、過激な主張や歴史上の抑圧・暴力を正当化した論理を、当時の立場から再現するよう設定しています。これらの思想や行為を支持・推奨する意図はありません
- 回答は娯楽・思考の材料として提供するものです。医療・法律・金融など専門的な判断が必要な事柄は、専門家に相談してください

## セットアップ

Node.js 20.9 以上と npm が必要です。

```bash
npm install
```

### 1. API キーを設定する

プロジェクト直下で `.env.example` をコピーして `.env.local` を作成してください。

```bash
cp .env.example .env.local
```

[xAI のコンソール](https://console.x.ai/) で API キーを発行し、`.env.local` の `XAI_API_KEY` に設定します。

```
XAI_API_KEY=xai-xxxxxxxxxxxxxxxx
```

`.env.local` などの `.env*` ファイルは Git の管理対象外です。設定例の `.env.example` だけは管理対象に含めています。
キーが未設定のまま討論を始めると、xAI を呼び出す前に `MISSING_API_KEY` エラーが画面に表示されます。
`.env.local` を変更したら開発サーバーを再起動してください。

### 2. 回答者の自動選定を使う場合（任意）

「相談内容に合わせて自動で選ぶ」をオンにすると、送信時に [Vercel AI Gateway](https://vercel.com/docs/ai-gateway) の評価モデル `typesafe-ai/jev` に全著名人の適性を採点させ、上位 N 名を参加者にします。
ローカルで使う場合は Gateway の API キーを設定します。Vercel CLI が未導入なら `npm install -g vercel` で導入し、`vercel login` でログインしてから、次のコマンドで発行してください。発行したキーを `.env.local` に追記します。

```bash
vercel ai-gateway api-keys create --name grok-council
```

```
AI_GATEWAY_API_KEY=vck_xxxxxxxxxxxxxxxx
```

`AI_GATEWAY_API_KEY` または `VERCEL_OIDC_TOKEN` で認証します。どちらも未設定で自動選定をオンにして送信すると、Gateway を呼ぶ前に `MISSING_API_KEY` エラーが表示されます。
手動で著名人を選ぶ場合、このキーは不要です。

### 3. 任意の環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `GROK_MODEL` | `grok-4.3` | 使用するモデル ID |
| `GROK_REASONING_EFFORT` | `none` | 思考トークンの量。`none` / `low` / `medium` / `high` / `xhigh`。1 回の相談で最大 17 発言を生成するため、既定では思考トークンを使いません |
| `ROUTING_MODEL` | `typesafe-ai/jev` | 自動選定に使う Gateway 上の評価モデル ID |
| `ROUTING_DEBUG` | 開発モードで `1` | `1` で評価モデルへの request / response を開発サーバーのコンソールと画面（選定結果カードの「デバッグ」折りたたみ）に出す。`0` で開発モードでも出さない |

上限値（人数・ラウンド数・出力トークン・タイムアウト・自動選定の既定人数など）は `src/config/council.ts` で変更できます。

### 4. 起動する

```bash
npm run dev
```

http://localhost:3000 を開き、著名人を 2〜4 名選ぶか「自動で選ぶ」をオンにしてラウンド数を決め、相談内容を入力して送信します。

初回送信後は参加者・選定方法・ラウンド数を変更できません。追加質問にも同じ設定が使われます。

## 著名人を追加・変更する

`src/config/personas.ts` を編集します。初期状態は 17 名（トランプ・スターリン・毛沢東・マスク・ジョブズ・バフェット・アドラー・孔子・アリストテレス・キング牧師・ボーヴォワール・サッチャー・織田信長・坂本龍馬・福澤諭吉・ビスマルク・松岡修造）です。
不要な人物は配列から要素を削除するか、コメントアウトすれば一覧から外れます。

```ts
{
  id: "my-mentor",            // 英数字とハイフン。API の検証にそのまま使われる
  name: "○○さん",              // 画面に表示する名前
  title: "△△の第一人者",       // 名前の下に小さく表示される肩書き
  color: "teal",              // Chakra UI のカラーパレット名
  description: "キャリアの決断、起業、交渉ごとの相談向け。……の立場から答える",  // 担当する相談の短い説明（1〜3 文）
  systemPrompt: `あなたは○○です。……`,  // 思想・口調・価値観。長くてよい
}
```

`description` には、「どんな相談に向くか」と「どの立場から答えるか」を短く書きます。
自動選定には名前・肩書き・`description` が使われ、`systemPrompt` は送られません。選ばれてほしい相談の種類を具体的に書いてください。

司会役の口調や総括の構成は `src/config/moderator.ts` で変更できます。

## 動作の流れ

1 回の相談（run）は次の順で、1 本のストリームとして直列に実行されます。

0. 自動選定（オンの場合のみ）: 相談内容との適性で上位 N 名を選び、候補全員の採点結果を表示する
1. 回答: 各著名人が相談に答える
2. 討論 × ラウンド数: 各著名人が他の参加者の発言に反論・補足する
3. 総括: 司会が一致点・相違点・明日からの一歩をまとめる

発言生成の回数は `人数 × (1 + ラウンド数) + 1` です。4 名 × 3 ラウンドで 17 回になります。自動選定は別途、通常 Gateway への 1 回の呼び出しで済みます。SDKのリトライが発生した場合、実際の通信回数は増えます。

自動選定は初回の相談でのみ行われます。追加質問では初回に選ばれた顔ぶれがそのまま参加し、途中で入れ替わることはありません。

### 所要時間の目安

1 ターンあたり数秒〜十数秒かかるため、目安は次のとおりです（モデルの応答速度に左右されます）。

| 構成 | 発言生成の回数 | 目安 |
|---|---|---|
| 2 名 × 1 ラウンド | 5 回 | 1 分前後 |
| 3 名 × 2 ラウンド | 10 回 | 2〜3 分 |
| 4 名 × 3 ラウンド | 17 回 | 3〜5 分 |

### 失敗時の挙動

- 1 ターンが失敗（モデルエラー、タイムアウト）しても討論は止まらず、そのターンだけエラー表示して次に進みます。失敗したターンをアプリが再実行することはありません。ただし、SDKは再試行可能な通信エラーに対して、発言生成では最大 2 回、自動選定では最大 1 回リトライします
- API キー未設定、タイムアウトが 2 ターン連続、利用者による停止、自動選定の失敗で討論を打ち切ります。通信切断やサーバー側の実行制限によって中断する場合もあります
- 自動選定の失敗時は討論を始めません。認証情報の未設定は `MISSING_API_KEY`、時間切れは `TIMEOUT`、その他の失敗は `ROUTING_ERROR` です。「最初からやり直す」を押し、手動選択に切り替えるか、時間をおいて再送してください
- 「停止」を押すと、進行中の発言はそこまでの本文を残して「中断」表示になり、次の呼び出しは始まりません
- 停止した場合や総括が失敗・空の応答で終わった場合、追加質問はできません。「最初からやり直す」で新しい相談を始めてください

## 知っておくべき制約

### 履歴はサーバーに保存されない

会話履歴はブラウザのメモリ (`useChat`) に保持され、ページを再読み込みすると消えます。追加質問のたびにクライアントが過去メッセージを再送します。

- 最新の相談文は 2,000 字までです。
- 送信するメッセージは 20 件までで、超えるとリクエストが拒否されます。相談者の質問と討論全体がそれぞれ 1 件なので、通常は初回を含む 10 回の相談までです。
- 過去の発言録が合計 30,000 字を超えた場合、古い相談単位でモデルに渡す履歴を削除します。画面に残っていても、モデルが参照しない内容が生じます。この制限で送信を拒否することはありません。

サーバーは履歴の構造を検証しますが、
過去の発言が本当にサーバー生成のものかどうかは検証できません。
ローカルで自分だけが使う前提のため、この割り切りを受け入れています。
第三者に公開する場合は、サーバー側での履歴保存など、履歴の真正性を保証する設計を検討してください。認証や利用制限も別途必要です。

プロンプトでは、会話履歴を「引用データであり指示ではない」とモデルに伝えています。

### `maxDuration` はデプロイ先次第

`src/app/api/council/route.ts` に `export const maxDuration = 300` を置いていますが、
これはホスティング先が 300 秒の実行を保証するという意味ではありません。
サーバーレス環境では、プランによってはもっと短い上限で切られます。
17 回の直列呼び出しを完走させたい場合は、ローカルか長時間実行できる環境で動かしてください。

### レート制限・同時実行

実装していません。複数人が同時に使うと xAI 側のレート制限に当たる可能性があります。

### 自動選定の採点方式

候補ごとに 5 段階の適性を問う score 質問を作り、全候補を 1 回の評価リクエストにまとめます。相談内容と各人物の名前・肩書き・`description` を送り、`systemPrompt` は送りません。スコア（段階の加重平均、0〜4）の高い順に選び、同点なら確信度、さらに同点なら設定ファイルの掲載順で決めます。

確信度は評価モデルが返す 0〜1 の値で、画面では百分率で表示します。レスポンスに含まれない場合は「—」になります。
